# apps/server — AGENTS.md

The Cloudflare Worker. Root rules in [/AGENTS.md](../../AGENTS.md) apply.

## Layout

```
src/
  index.ts                  Entry: default export (fetch router + email handler) + every bound Durable Object class. Exports only.
  http/
    router.ts               HTTP routing. Decides which user's agent a request reaches.
    responses.ts            no-store headers, JSON responses
  auth/
    google.ts               /auth/login, /auth/callback, /auth/logout
    session.ts              Signed session (cookie or Bearer), current user, ALLOWED_EMAILS
    native.ts               Native-app sign-in: PKCE code → /auth/token
    signing.ts              HMAC-signed values shared by sessions and codes
    cookies.ts              Cookie read/write helpers
  agents/
    common/                 Shared by both harnesses: persona + memory prompt, reminders
    think/
      assistant.ts          Assistant DO: Think hooks + callables, delegating to the files below
      store.ts              Its SQLite tables (settings, owner, Telegram and email config, memories)
      model.ts              Settings → model (Workers AI / OpenAI / Anthropic / Google)
      system-prompt.ts      System prompt
      tools/                AI SDK tools by group (memory, reminders, sandbox, research, email)
    pi/
      pi-assistant.ts       PiAssistant DO: one Pi agent per turn
      model.ts              Workers AI model over REST
      system-prompt.ts      System prompt
      tools.ts              Pi (TypeBox) tools
      transcript.ts         UI messages → Pi transcript
      ui-stream.ts          Pi events → AI SDK UI stream
  integrations/telegram/    Per-user bots; see its README.md (TelegramRoutes DO lives here)
  integrations/email/       Each assistant's own address; see its README.md (EmailAddresses DO lives here)
  tools/                    Capabilities the agents call (browser, code runner, knowledge, sandbox DO)
wrangler.jsonc              Bindings, Durable Objects, migrations, routes
env.d.ts                    Generated by `bun run types` — never edit by hand
```

## Rules

- **Routing is the security boundary.** The Worker, not the client, picks the
  agent instance (`google:<sub>`). Never add a generic `/agents/*` route or
  let a client choose an instance name.
- **New Durable Object class**: export it from `src/index.ts`, add the
  binding and a new `migrations` tag in `wrangler.jsonc`, then
  `bun run types`.
- **New path the Worker must handle**: add it to `assets.run_worker_first`
  in `wrangler.jsonc` (otherwise the SPA fallback answers it) and, if a
  client calls it, to `AUTH_ROUTES` / `HARNESSES` in `@cot/shared`.
- **New callable**: add it to `AssistantRpc` in `@cot/shared` first, then
  implement it with `@callable()`. Validate every argument; it comes from the
  network.
- **Durable Object classes stay thin.** They implement SDK hooks and
  callables and delegate: storage to a `store.ts`, prompts to
  `system-prompt.ts`, tools to `tools/`, integrations to a channel class.
- **New tool**: put the capability in `src/tools/<name>.ts` (a plain function
  of `env` + input), then wrap it as an AI SDK tool in the matching
  `agents/think/tools/<group>.ts` (or a new group added to
  `tools/index.ts`). Tools that change state outside the chat (commands,
  file writes) need approval; add them to `NEEDS_APPROVAL` so they're
  withheld from Telegram turns.
- **New integration** (Slack, email, …): a folder
  `src/integrations/<name>/` modelled on `telegram/` (config, API client,
  gate, webhook, and a channel class the assistant delegates to). Secrets
  are stored in the user's agent, never in the client.
- Return tool errors as text (`String(error)`) so the model can recover;
  throw from callables so the client sees a rejected promise.
- The Worker is compiled without the DOM lib. Code that runs in a browser
  page (Puppeteer `evaluate`) must declare the globals it reads.
